1 Product Scope & Non-Goals 
🎯 Цели продукта (MVP Scope)
Главная цель:
Разработать MVP ИИ-агента для подбора автомобилей с веб-интерфейсом и полнофункциональной административной панелью для управления каталогом и мониторинга системы.
Ключевые возможности MVP:
1. Пользовательский интерфейс (Frontend)
Веб-чат для текстовых запросов на естественном языке
Отображение структурированных JSON-фильтров парсинга
Минималистичный UI с историей последних 10 диалогов
2. LLM-парсинг и обработка
Преобразование запросов → JSON-фильтры (марка, модель, кузов, техпараметры)
>85% точность парсинга с 4-уровневым fallback
Pydantic-валидация + нормализация данных
Логирование всех запросов/ответов для анализа
3. Административная панель (Core функционал)
Управление каталогом (до 50К записей):
Загрузка/обновление XML/JSON файлов Auto.ru
Поиск, просмотр, редактирование записей
Валидация данных + массовые операции
История изменений (audit log)

⚙️ 3.3 BUSINESS RULES
Парсинг (всегда работает):
text
Текст → LLM → JSON (97%) → Pydantic validate
FAIL → Retry/Fix (2%) → Keyword (0.8%) → Template (0.2%)
≥3 фильтра → SUCCESS | <3 → "Уточните запрос"
Поиск (условный):
text
if catalog_status == "loaded":
results = SQL(filters).limit(5)
else:
results = null
Каталог:
text
Max: 50К записей | XML/JSON only | Дубликаты → merge
Обязательные: mark_name, year, price

**from** pydantic **import** BaseModel  
**from** typing **import** Optional  
**class** AutoRuSearchFilters(BaseModel):  
mark\_name: Optionalstr \= None  
folder\_name: Optionalstr \= None  
modification\_name: Optionalstr \= None  
tech\_param\_id: Optionalstr \= None  
body\_type: Optionalstr \= None  
years: Optionalstr \= None  
MASTER\_PROMPT \= """  
промпт выше с few-shot  
"""  
**async\*\*\*\*def** parse\_query(user\_text: str):  
prompt \= MASTER\_PROMPT.format(user\_text=user\_text)  
response \= **await** openai.chat.completions.create(  
model="gpt-4o-mini",  
messages={"role": "user", "content": prompt},  
response\_format={"type": "json\_object"}  
)  
filters \= AutoRuSearchFilters.model\_validate\_json(response.choices0.message.content)  
*\# SQL-запрос по нормализованным полям*  
sql\_results \= **await** execute\_search(filters)  
**return** {"filters": filters.dict(), "results": sql\_results}

🛡️ 13.1 MULTI-AGENT SYSTEM

Реализована мультиагентная архитектура для повышения безопасности и качества парсинга:

text
Запрос пользователя
         │
         ▼
┌─────────────────────────┐
│  🛡️ Security Agent      │  ← Проверяет безопасность запроса
│  - Prompt injection     │     (LLM + regex fallback)
│  - Off-topic запросы    │
│  - Toxic контент        │
└───────────┬─────────────┘
            │ safe ✓
            ▼
┌─────────────────────────┐
│  🔍 Parser Agent        │  ← Извлекает JSON фильтры
│  - Понимает сленг       │     (few-shot learning)
│  - Валидация полей      │
└───────────┬─────────────┘
            │
            ▼
       Результаты

Конфигурация агентов (backend/src/config/agents.js):
javascript
module.exports = {
  security: {
    enabled: true,
    model: process.env.SECURITY_AGENT_MODEL || 'deepseek/deepseek-chat',
  },
  parser: {
    model: process.env.PARSER_AGENT_MODEL || 'deepseek/deepseek-chat',
  },
};

Security Agent возвращает:
json
{
  "safe": true|false,
  "category": "car_search|injection|off_topic|toxic",
  "reason": "описание",
  "method": "llm|regex"
}

## 🎨 14.1 POST-SEARCH FILTER CHIPS (Feature 002)

**Implemented:** 2026-02-12 | **PR:** #2 | **Spec:** specs/002-post-search-filters/

### Описание

Динамические фильтры-уточнения для мгновенной фильтрации результатов поиска на клиенте без повторных запросов к LLM/бекенду. После выполнения поиска пользователь видит чипсы-фильтры, сгенерированные из реальных данных найденных автомобилей.

### Функциональность

**5 групп фильтров:**
- Тип двигателя (дизель, бензин, гибрид, электро)
- КПП (АКПП, МКПП, вариатор, робот)
- Привод (передний, задний, полный)
- Тип кузова (седан, внедорожник, универсал и т.д.)
- Год выпуска (конкретные года из результатов)

**Ключевые возможности:**
- ✅ Мгновенная клиентская фильтрация (без API запросов)
- ✅ Динамические счётчики на чипсах: "дизель (6)"
- ✅ Faceted counts (счётчики учитывают другие активные фильтры)
- ✅ Логика AND между группами, OR внутри группы
- ✅ Disabled-чипсы для невозможных комбинаций (показываются с (0))
- ✅ Auto-reset при новом поиске
- ✅ Кнопка "Сбросить фильтры"
- ✅ Null-значения всегда проходят фильтр
- ✅ Совместимость с "Показать ещё" (pagination)

### Архитектура

**Frontend (FSD):**

```
frontend/src/features/search/
├── model/
│   └── useFilterChips.js      # Хук с логикой фильтрации (115 строк)
│       ├── FILTER_GROUPS константа (5 групп)
│       ├── activeFilters state (объект {groupKey: [values]})
│       ├── toggleFilter(groupKey, value)
│       ├── resetFilters()
│       ├── filteredCars (useMemo - AND/OR логика)
│       └── chipGroups (useMemo - faceted counts)
│
└── ui/
    └── FilterChips.jsx        # UI компонент (43 строки)
        ├── Render chip groups
        ├── 3 состояния: inactive/active/disabled
        └── Кнопка "Сбросить фильтры"
```

**Интеграция:**

```javascript
// pages/SearchPage/index.jsx
const { chipGroups, filteredCars, toggleFilter, resetFilters } =
  useFilterChips(result?.results || []);

// Передаётся в CarResults.jsx
<CarResults
  chipGroups={chipGroups}
  filteredCars={filteredCars}
  onToggleFilter={toggleFilter}
  onResetFilters={resetFilters}
/>
```

### Технические детали

**Логика фильтрации (useFilterChips.js):**

```javascript
// AND между группами, OR внутри группы
filteredCars = cars.filter(car =>
  activeGroupKeys.every(groupKey => {
    const val = car[groupKey];
    if (val == null || val === "") return true;  // FR-011
    return activeFilters[groupKey].includes(String(val));
  })
);

// Faceted counts (Decision 4)
const baseForCounts = cars.filter(car =>
  otherGroupKeys.every(gk => {
    const val = car[gk];
    if (val == null) return true;
    return activeFilters[gk].includes(String(val));
  })
);
```

**UI состояния (Tailwind CSS v4):**

```javascript
// Inactive
className: "bg-slate-700 text-slate-300 hover:bg-slate-600"

// Active
className: "bg-cyan-600 text-white"

// Disabled (count = 0)
className: "bg-slate-800 text-slate-600 cursor-not-allowed opacity-50"
```

### Performance

- **Мгновенная фильтрация:** <16ms на 50 результатов (useMemo оптимизация)
- **No backend calls:** чисто клиентская логика
- **Lazy computation:** faceted counts пересчитываются только при изменении activeFilters

### Edge Cases (обработаны)

1. **Null values:** Авто с пустыми значениями полей всегда проходят фильтр (не скрываются)
2. **Single value groups:** Группы с <=1 уникальным значением автоматически скрываются
3. **Empty results:** Показывается сообщение "Нет авто по выбранным фильтрам"
4. **Pagination:** Новые результаты при "Показать ещё" также фильтруются
5. **New search:** Фильтры автоматически сбрасываются при новом поиске

### Metrics (из spec.md)

- **SC-001:** Фильтрация мгновенная (пользователь не замечает задержки) ✅
- **SC-002:** Сужение результатов за 2-3 клика без повторного поиска ✅
- **SC-003:** Корректное количество результатов или сообщение при 0 совпадений ✅
- **SC-004:** Новый поиск всегда с чистого состояния фильтров ✅
