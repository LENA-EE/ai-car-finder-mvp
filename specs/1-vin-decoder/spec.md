# Feature Specification: VIN Decoder MVP

**Feature Branch**: `1-vin-decoder`
**Created**: 2026-02-21
**Status**: Draft
**Input**: VIN Decoder MVP - сервис проверки автомобилей по VIN номеру. Расшифровка VIN + проверка по бесплатным API (ГИБДД, ФНП, ФССП). MCP сервер для интеграции с Claude.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Расшифровка VIN (Priority: P1)

Пользователь вводит VIN номер и получает полную расшифровку: марка, модель, год выпуска, страна производства, тип двигателя, комплектация.

**Why this priority**: Базовая функциональность, работает без внешних API, даёт мгновенную ценность.

**Independent Test**: Можно протестировать вводом любого VIN — сразу видна расшифровка без зависимости от внешних сервисов.

**Acceptance Scenarios**:

1. **Given** пользователь на странице поиска, **When** вводит валидный VIN "WBAPH5C55BA123456", **Then** видит расшифровку: BMW, 5 серия, 2011 год, Германия, бензин
2. **Given** пользователь вводит VIN, **When** VIN невалидный (неверная контрольная сумма), **Then** видит сообщение "Неверный VIN номер"
3. **Given** пользователь вводит VIN, **When** VIN слишком короткий/длинный, **Then** видит сообщение о необходимости 17 символов

---

### User Story 2 - Проверка истории в ГИБДД (Priority: P1)

Пользователь получает данные из ГИБДД: количество ДТП, число владельцев, нахождение в розыске, ограничения на регистрацию.

**Why this priority**: Критически важная информация для покупателя, бесплатный API.

**Independent Test**: После расшифровки VIN нажать "Проверить историю" и увидеть данные ГИБДД.

**Acceptance Scenarios**:

1. **Given** расшифрованный VIN, **When** пользователь запрашивает проверку ГИБДД, **Then** видит количество ДТП с датами
2. **Given** расшифрованный VIN, **When** авто в розыске, **Then** видит предупреждение красным цветом
3. **Given** расшифрованный VIN, **When** сервис ГИБДД недоступен, **Then** видит сообщение "Сервис временно недоступен" с возможностью повторить

---

### User Story 3 - Проверка залогов (Priority: P2)

Пользователь проверяет, находится ли автомобиль в залоге у банка через реестр ФНП (Федеральная нотариальная палата).

**Why this priority**: Важная информация, но реже встречается чем ДТП.

**Independent Test**: Проверить VIN на наличие записей о залоге.

**Acceptance Scenarios**:

1. **Given** расшифрованный VIN, **When** авто в залоге, **Then** видит информацию о залогодержателе и дате залога
2. **Given** расшифрованный VIN, **When** авто не в залоге, **Then** видит зелёную отметку "Залогов не найдено"

---

### User Story 4 - Проверка ограничений ФССП (Priority: P2)

Пользователь проверяет наличие ограничений от судебных приставов на регистрационные действия.

**Why this priority**: Дополнительная проверка безопасности сделки.

**Independent Test**: Проверить VIN на ограничения от ФССП.

**Acceptance Scenarios**:

1. **Given** расшифрованный VIN, **When** есть ограничения ФССП, **Then** видит список ограничений с номерами исполнительных производств
2. **Given** расшифрованный VIN, **When** ограничений нет, **Then** видит зелёную отметку "Ограничений не найдено"

---

### User Story 5 - MCP интеграция с Claude (Priority: P3)

Claude может использовать VIN декодер как инструмент для проверки автомобилей в диалоге.

**Why this priority**: Расширяет возможности AI Car Finder, но требует отдельной инфраструктуры MCP.

**Independent Test**: В Claude Desktop вызвать инструмент check_vin с параметром VIN.

**Acceptance Scenarios**:

1. **Given** MCP сервер запущен, **When** Claude вызывает tool "decode_vin", **Then** получает JSON с расшифровкой
2. **Given** MCP сервер запущен, **When** Claude вызывает tool "check_vin_history", **Then** получает JSON с историей из всех источников

---

### User Story 6 - Интеграция в поиск машин (Priority: P3)

После поиска машины в AI Car Finder пользователь может ввести VIN найденного авто и проверить его.

**Why this priority**: Связывает новую функциональность с существующим продуктом.

**Independent Test**: На странице результатов поиска нажать "Проверить VIN" у конкретной машины.

**Acceptance Scenarios**:

1. **Given** пользователь нашёл машину в каталоге, **When** нажимает "Проверить VIN", **Then** открывается форма ввода VIN
2. **Given** введён VIN, **When** проверка завершена, **Then** результат отображается рядом с карточкой машины

---

### Edge Cases

- Что происходит при вводе VIN с пробелами или дефисами? → Автоматически очищаем
- Как обрабатываем кириллические символы (А вместо A)? → Автоматически заменяем на латиницу
- Что если VIN содержит буквы I, O, Q (запрещены в VIN)? → Показываем ошибку
- Как обрабатываем таймаут внешних API? → Показываем частичный результат + статус недоступных сервисов
- Что если один сервис вернул ошибку? → Показываем результаты доступных сервисов

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА валидировать VIN по стандарту ISO 3779 (17 символов, контрольная сумма)
- **FR-002**: Система ДОЛЖНА расшифровывать WMI код (символы 1-3) в производителя и страну
- **FR-003**: Система ДОЛЖНА определять год выпуска по 10-му символу VIN
- **FR-004**: Система ДОЛЖНА запрашивать данные ГИБДД по VIN (ДТП, владельцы, розыск, ограничения)
- **FR-005**: Система ДОЛЖНА запрашивать реестр залогов ФНП
- **FR-006**: Система ДОЛЖНА запрашивать данные ФССП об ограничениях
- **FR-007**: Система ДОЛЖНА кэшировать результаты проверок на 24 часа
- **FR-008**: Система ДОЛЖНА предоставлять MCP-совместимые инструменты для Claude
- **FR-009**: Система ДОЛЖНА логировать все проверки для аналитики
- **FR-010**: Система ДОЛЖНА обрабатывать недоступность внешних сервисов gracefully

### Key Entities

- **VIN**: 17-символьный идентификатор (WMI + VDS + VIS), страна, производитель, год, характеристики
- **VinCheck**: Результат проверки VIN (VIN, дата проверки, источники, результаты по каждому источнику)
- **CheckSource**: Источник данных (ГИБДД, ФНП, ФССП) со статусом и временем ответа
- **Accident**: Запись о ДТП (дата, регион, тип повреждений)
- **Pledge**: Запись о залоге (залогодержатель, дата начала, номер договора)
- **Restriction**: Ограничение ФССП (тип, номер производства, дата)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Расшифровка VIN выполняется менее чем за 100 миллисекунд
- **SC-002**: Полная проверка по всем источникам завершается менее чем за 10 секунд
- **SC-003**: 99% валидных VIN успешно расшифровываются
- **SC-004**: При недоступности одного источника, остальные проверки выполняются успешно
- **SC-005**: Пользователь понимает результат проверки без дополнительных пояснений (цветовая индикация: зелёный/жёлтый/красный)
- **SC-006**: MCP инструменты отвечают в формате, совместимом с Claude Desktop

## Assumptions

- API ГИБДД доступен публично (гибдд.рф/check/auto)
- Реестр залогов ФНП доступен (reestr-zalogov.ru)
- Данные ФССП доступны через открытый API
- WMI справочник (производители) можно собрать из открытых источников
- Пользователь вводит VIN вручную (нет OCR распознавания)

## Out of Scope

- Платные проверки (Автотека, Автокод)
- OCR распознавание VIN с фото
- История техосмотров
- Проверка пробега
- Интеграция с Auto.ru/Avito
