# Research: Обогащение результатов поиска стоимостью обслуживания

**Branch**: `001-service-cost-enrichment` | **Date**: 2026-02-08

## R1: Архитектура обогащения — синхронная vs асинхронная

**Decision**: Асинхронная загрузка через отдельный endpoint

**Rationale**:
- Спецификация требует прогрессивного отображения (FR-013, FR-014)
- Основной поиск (`POST /api/v1/parse`) не должен замедляться
- Фронтенд сначала отображает результаты, затем запрашивает обогащение
- Это сохраняет существующий API контракт без изменений (Constitution: API контракты не меняются)

**Alternatives considered**:
- Синхронное обогащение в parse controller — отвергнуто: замедляет основной поиск, нарушает принцип graceful degradation, меняет response format
- Server-Sent Events (SSE) — отвергнуто: overengineering для данной задачи (YAGNI), требует дополнительной инфраструктуры

## R2: Внешний API — auto.dev Maintenance Cost API

**Decision**: Использовать auto.dev API для получения данных обслуживания

**Rationale**:
- auto.dev предоставляет данные по марке/модели/двигателю
- REST API с JSON ответами
- Поддержка batch-запросов через параллельные вызовы

**Integration pattern**:
- HTTP GET запросы с параметрами make, model, engine_type
- Таймаут 3 секунды (FR-005)
- Ответ валидируется: числовые значения > 0 (edge case из спецификации)
- При ошибке — возвращаем null для конкретного авто, не прерываем весь batch

**Alternatives considered**:
- Статическая таблица стоимостей в БД — отвергнуто: трудно поддерживать актуальность, требует ручного обновления
- Scraping — отвергнуто: ненадёжно, нарушает ToS

## R3: Стратегия кеширования

**Decision**: PostgreSQL таблица `maintenance_cache` с TTL 24 часа

**Rationale**:
- Уже есть PostgreSQL — не добавляем новую зависимость (Simplicity & YAGNI)
- 24-часовой TTL достаточен — стоимость обслуживания меняется редко
- Ключ кеша: `mark_name + folder_name + engine_type` (гранулярность из clarify)
- Простой механизм: при запросе проверяем кеш → если свежий, возвращаем → если нет, обращаемся к API → сохраняем

**Alternatives considered**:
- Redis — отвергнуто: новая зависимость, неоправданная сложность для MVP
- In-memory cache (Map) — отвергнуто: не переживает перезапуск, не шарится между инстансами
- Без кеша — отвергнуто: каждый запрос к API, проблемы с rate limiting и производительностью

## R4: Batch-запрос обогащения

**Decision**: `POST /api/v1/maintenance/batch` с массивом автомобилей

**Rationale**:
- Один HTTP-запрос от фронтенда вместо N отдельных
- Backend параллельно проверяет кеш и запрашивает API для промахов
- Дедупликация: если в результатах 3 BMW X5 diesel — один запрос к API
- Promise.allSettled для параллельных запросов — один сбой не блокирует остальные

**Alternatives considered**:
- Отдельный GET для каждого авто — отвергнуто: N запросов от фронтенда, лишняя нагрузка
- WebSocket — отвергнуто: overengineering (YAGNI)

## R5: UX загрузки и отображения

**Decision**: Анимированный скелетон "Рассчитываем стоимость обслуживания..." → плавная замена на данные

**Rationale**:
- Прогрессивная загрузка: карточки видны сразу, обогащение появляется позже
- Три состояния компонента MaintenanceInfo: loading → loaded → unavailable
- Пометка "приблизительные данные" если сопоставление только по марке + модели (FR-012)
- Плавная анимация перехода (FR-014)

**Alternatives considered**:
- Полный спиннер на странице — отвергнуто: блокирует просмотр результатов
- Без индикации загрузки — отвергнуто: пользователь не поймёт, что данные подгружаются

## R6: Обработка ошибок и наблюдаемость

**Decision**: Логирование неудачных обогащений в существующий error_graveyard + console.warn

**Rationale**:
- Используем существующий паттерн логирования (error_graveyard)
- Не создаём новую инфраструктуру мониторинга (YAGNI)
- console.warn для операционной отладки в Docker logs
- Метрики: enrichment_success_rate, enrichment_latency_ms добавляются к ответу batch endpoint

**Alternatives considered**:
- Отдельная таблица enrichment_logs — отвергнуто: дублирование существующего паттерна
- Внешний мониторинг (Sentry, DataDog) — отвергнуто: не в scope MVP
