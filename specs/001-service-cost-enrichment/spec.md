# Feature Specification: Обогащение результатов поиска стоимостью обслуживания

**Feature Branch**: `001-service-cost-enrichment`
**Created**: 2026-02-08
**Status**: Draft
**Input**: User description: "Добавить к результатам поиска авто информацию о стоимости обслуживания (годовая стоимость, стоимость на км, источник данных) с graceful degradation при недоступности внешнего источника"

## Clarifications

### Session 2026-02-08

- Q: Стратегия кеширования данных обслуживания? → A: Кеш на 24 часа — данные сохраняются и обновляются раз в сутки
- Q: Гранулярность сопоставления данных обслуживания? → A: Марка + модель + тип двигателя. Если точное совпадение найдено — показываем точные данные. Если запрос менее конкретный (только марка + модель) — показываем с пометкой "приблизительные данные"
- Q: Как отображаются результаты во время загрузки данных обслуживания? → A: Прогрессивно — результаты поиска показываются сразу, на месте данных обслуживания отображается анимированная индикация "Рассчитываем стоимость обслуживания...", которая заменяется реальными данными после загрузки

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Просмотр стоимости обслуживания (Priority: P1)

Пользователь ищет автомобиль и видит не только цену покупки, но и среднюю годовую стоимость обслуживания, стоимость на километр пробега и источник данных. Это позволяет принять обоснованное решение о покупке, сравнивая реальную стоимость владения разными автомобилями.

**Why this priority**: Основная ценность фичи. Без отображения стоимости обслуживания фича не имеет смысла. Два автомобиля по одной цене могут различаться в 2-3 раза по расходам на обслуживание.

**Independent Test**: Выполнить поиск "бумер x5 дизель до 5 млн" и убедиться, что каждая карточка авто содержит информацию о стоимости обслуживания, стоимости на км и источнике данных.

**Acceptance Scenarios**:

1. **Given** пользователь выполнил поиск и получил список автомобилей, **When** результаты отображаются, **Then** для каждого автомобиля показана средняя годовая стоимость обслуживания в рублях
2. **Given** пользователь видит карточку автомобиля с данными обслуживания, **When** он смотрит на детали, **Then** отображается стоимость на километр пробега и указан источник данных
3. **Given** пользователь ищет два автомобиля с одинаковой ценой покупки, **When** результаты отображаются, **Then** он может сравнить их по стоимости обслуживания
4. **Given** пользователь выполнил поиск, **When** результаты появляются на экране, **Then** карточки авто показываются сразу, а на месте данных обслуживания отображается анимация "Рассчитываем стоимость обслуживания...", которая заменяется реальными данными после загрузки

---

### User Story 2 - Graceful degradation при недоступности данных (Priority: P1)

Если внешний источник данных недоступен, медленный или не содержит информации для конкретного автомобиля, пользователь всё равно получает результаты поиска. Основная функция поиска никогда не ломается из-за обогащения.

**Why this priority**: Критически важно для надёжности системы. Внешний источник данных не должен быть single point of failure. Это соответствует принципу Graceful Degradation из конституции проекта.

**Independent Test**: Отключить доступ к внешнему источнику данных и выполнить поиск — результаты должны отображаться без стоимости обслуживания, без ошибок для пользователя.

**Acceptance Scenarios**:

1. **Given** внешний источник данных полностью недоступен, **When** пользователь выполняет поиск, **Then** результаты отображаются без информации о стоимости обслуживания, без сообщений об ошибке
2. **Given** внешний источник данных отвечает медленно (более 3 секунд), **When** пользователь выполняет поиск, **Then** запрос к источнику прерывается и результаты возвращаются без обогащения
3. **Given** внешний источник не содержит данных для конкретного редкого автомобиля, **When** пользователь видит этот автомобиль в результатах, **Then** отображается сообщение "Данные недоступны" вместо стоимости обслуживания
4. **Given** внешний источник возвращает ошибку для одного авто из списка, **When** результаты отображаются, **Then** это авто показано без стоимости обслуживания, остальные авто — с полными данными

---

### User Story 3 - Прозрачность источника данных (Priority: P2)

Пользователь видит, откуда взяты данные о стоимости обслуживания, что повышает доверие к информации.

**Why this priority**: Важно для доверия пользователей, но не блокирует основную функциональность.

**Independent Test**: Найти авто с данными обслуживания и убедиться, что указан источник данных.

**Acceptance Scenarios**:

1. **Given** для автомобиля доступны данные обслуживания, **When** пользователь видит карточку, **Then** указан источник данных (например, "auto.dev")

---

### Edge Cases

- Внешний источник данных полностью недоступен — результаты отображаются без обогащения, без ошибок для пользователя
- Источник возвращает ошибку для конкретного авто — это авто показывается без стоимости обслуживания, остальные — с данными
- Источник отвечает дольше 3 секунд — запрос прерывается, результаты возвращаются без обогащения
- Для редкого авто нет данных — отображается "Данные недоступны"
- Данные обслуживания равны нулю или отрицательные — такие данные считаются невалидными и не отображаются
- Запрос содержит только марку без модели — данные обслуживания не показываются (слишком широкий разброс)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST автоматически обогащать каждый найденный автомобиль данными о средней годовой стоимости обслуживания (ТО, запчасти) в рублях
- **FR-002**: Система MUST отображать стоимость обслуживания на километр пробега для каждого автомобиля
- **FR-003**: Система MUST указывать источник данных о стоимости обслуживания для прозрачности
- **FR-004**: Система MUST возвращать результаты поиска без обогащения, если внешний источник данных полностью недоступен
- **FR-005**: Система MUST прерывать запрос к внешнему источнику, если ответ занимает более 3 секунд, и возвращать результаты без обогащения
- **FR-006**: Система MUST показывать автомобиль без стоимости обслуживания, если внешний источник вернул ошибку для этого конкретного авто
- **FR-007**: Система MUST отображать сообщение "Данные недоступны", если для конкретного автомобиля нет данных о стоимости обслуживания во внешнем источнике
- **FR-008**: Добавление обогащения MUST NOT увеличивать общее время ответа поиска более чем на 2 секунды в нормальном режиме работы
- **FR-009**: Система MUST NOT ломать основную функцию поиска при любых проблемах с обогащением данных
- **FR-010**: Система MUST кешировать полученные данные обслуживания на 24 часа, чтобы избежать повторных запросов к внешнему источнику для одних и тех же автомобилей
- **FR-011**: Система MUST сопоставлять данные обслуживания по марке + модели + типу двигателя для максимальной точности
- **FR-012**: Если точное совпадение по типу двигателя недоступно, система MUST показывать данные по марке + модели с пометкой "приблизительные данные"
- **FR-013**: Система MUST отображать результаты поиска немедленно, а данные обслуживания подгружать асинхронно с анимированной индикацией "Рассчитываем стоимость обслуживания..."
- **FR-014**: После загрузки данных обслуживания индикация MUST плавно замениться реальными данными без перезагрузки страницы

### Key Entities

- **Данные обслуживания (MaintenanceCost)**: Средняя годовая стоимость обслуживания, стоимость на километр, источник данных, признак точности (точные / приблизительные). Привязывается к марке, модели и типу двигателя автомобиля.
- **Автомобиль (Car)**: Существующая сущность, расширяется опциональными данными обслуживания при отображении результатов поиска.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для 80%+ автомобилей в результатах поиска отображается стоимость обслуживания (при доступном источнике данных)
- **SC-002**: При недоступности внешнего источника данных 100% поисковых запросов продолжают возвращать результаты без ошибок
- **SC-003**: Общее время ответа поиска с обогащением не превышает время без обогащения более чем на 2 секунды
- **SC-004**: Пользователь может сравнить стоимость владения двумя автомобилями за менее чем 10 секунд после получения результатов

## Scope Boundaries

### Not Included in Current Version

- Проверка наличия у дилеров
- Геолокация пользователя
- Страховые расходы
- Стоимость топлива
- История ремонтов конкретного VIN

### Future Phases

1. Интеграция с базой дилеров (и цены)
2. Учёт геолокации для поиска ближайших дилеров
3. Калькулятор полной стоимости владения (TCO)

## Assumptions

- Внешний источник данных (auto.dev) предоставляет информацию о стоимости обслуживания по марке, модели и поколению автомобиля
- Данные о стоимости обслуживания являются средними и могут отличаться в зависимости от региона и конкретного экземпляра
- Стоимость обслуживания указывается в рублях
- Средний годовой пробег для расчёта стоимости на км принимается 15 000 км (стандарт для российского рынка)
- Данные обслуживания кешируются на 24 часа; повторные запросы в течение суток обслуживаются из кеша
